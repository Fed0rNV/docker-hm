# ДЗ 3 — Docker

Приложение со счётчиком из задания. Код в `app/` не менялся.
В `compose.yaml` запускаются приложение и Redis. Данные Redis сохраняются
в именованном volume, включена запись на диск через AOF.

## Запуск

Нужны Docker с Compose и curl. Команды выполняются из папки проекта:

```sh
cp .env.example .env
docker compose up -d --build --wait --wait-timeout 120
```

В `.env` можно поменять приветствие (`GREETING`) и порт (`HOST_PORT`, по умолчанию 8080).
После изменения настроек нужно повторить `docker compose up -d`.
Приложение доступно по адресу http://127.0.0.1:8080/.
Если поменять порт, его нужно заменить и в командах ниже.

Посмотреть счётчик и увеличить его на один:

```sh
curl -fsS http://127.0.0.1:8080/
curl -fsS -X POST http://127.0.0.1:8080/increment
```

Посмотреть логи и остановить контейнеры:

```sh
docker compose logs
docker compose down
```

Обычный `down` сохраняет данные. `down -v` удаляет volume вместе со счётчиком.

## Проверки

```sh
./scripts/run-all.sh
```

Сначала проверяются одиночный контейнер и Compose с SQLite,
затем два раза запускается проверка с Redis. Для SQLite есть отдельный
файл `compose.sqlite.yaml`.

В проверке с Redis счётчик увеличивается до 5. После пересоздания приложения
и после `down/up` значение должно остаться 5. При остановленном Redis
`/healthz` возвращает 200, а `/readyz` и `/increment` — 503.
После запуска Redis счётчик снова доступен без перезапуска приложения.
Также проверяются резервная копия и восстановление в новом проекте.
Тестовые проекты и их volumes удаляются автоматически.

У приложения заданы ограничения: UID 10001, файловая система только для чтения,
256 MiB памяти и одно ядро CPU. У обоих сервисов есть healthcheck.
Redis доступен внутри Compose по имени `redis`; наружу открыт только порт приложения.
